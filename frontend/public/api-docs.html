接入指南

从一次状态查询开始，再按需接入控制与实时数据。各接口的参数和响应结构见下方接口参考。

01 · 地址、认证与权限

当前实例的基础地址：/api/v1。请求和响应默认使用 JSON；时间戳为 Unix 秒，可含小数。

在控制台「设置 → 开发者 API」为每个应用创建独立的访问令牌，并按需选择只读或控制权限。

权限能力凭据
read状态、历史、场景查询和 OLED 预览只读令牌
control包含 read，并可控制硬件、保存和应用场景控制令牌
admin包含 control，并可管理令牌和其他设备目录网页登录会话

脚本使用 Authorization: Bearer <token>。已登录的浏览器自动携带会话 Cookie；带 Cookie 的写请求还需要 X-Pi-Control: 1。本文档的调试器会自动添加该请求头。

点击下方 Authorize 可用独立令牌调试，输入完整 pc_… 值即可。调试器不把令牌保存在浏览器持久化存储中。

02 · 第一次调用：cURL 与 Python

cURL / Bash · 查询状态

export PI_CONTROL_URL="__ORIGIN__"
read -rsp 'API token: ' PI_CONTROL_TOKEN
printf '\n'
export PI_CONTROL_TOKEN

curl --fail-with-body \
  -H "Authorization: Bearer $PI_CONTROL_TOKEN" \
  "$PI_CONTROL_URL/api/v1/status"

响应包含 version、目标配置 config、最近成功写入状态 applied、实时指标 metrics 和硬件连接信息 hardware。字段及示例见 GET /status。

Python 标准库 · 读取配置并将机箱风扇设为 3 档

沿用上面的环境变量。此示例会实际修改机箱风扇。

import json, os, uuid
from urllib.request import Request, urlopen
from urllib.error import HTTPError

base = os.environ["PI_CONTROL_URL"].rstrip("/") + "/api/v1"
headers = {"Authorization": "Bearer " + os.environ["PI_CONTROL_TOKEN"],
           "Content-Type": "application/json"}

def call(path, method="GET", body=None):
    data = None if body is None else json.dumps(body).encode()
    with urlopen(Request(base + path, data=data, headers=headers,
                         method=method), timeout=10) as response:
        return json.load(response)

state = call("/status")
fan = {**state["config"]["fan"], "mode": "manual", "level": 3}
command = {"expected_version": state["version"],
           "request_id": str(uuid.uuid4()), "value": fan}
try:
    result = call("/fans/case", "PUT", command)
    print(result["applied"]["fan"])
except HTTPError as error:
    print(error.code, error.read().decode())
03 · 更新配置、并发与重试
  1. GET /status 读取当前 version 及资源配置。
  2. 基于原配置修改需要的字段；value 是替换配置，省略字段会采用默认值。
  3. 使用新的 UUID 作为 request_id，同时提交 expected_version 和 value。
  4. 成功时使用响应中的新状态更新客户端；409 时重新读取，并由客户端决定是否仍要提交。

网络超时后，可在事件保留期内用同一调用者、同一 request_id、同一资源和配置重试，已成功的操作不会重复执行。服务端会返回当前状态，而不保证是原响应的逐字副本。同一编号用于不同操作会返回 409。

503 表示硬件写入失败，目标配置可能已持久化。先查询状态并检查 config、applied 和 hardware.errors；确认需要新操作时，使用新的请求编号。不要对 409 / 503 无条件循环重试。

硬件连接配置使用单独的 revision / expected_revision，从 GET /hardware 获取，不使用上面的控制配置版本。

04 · 历史分页与常见错误

事件和 OLED 帧按 id 倒序。首轮 ?before=0&limit=30，下一轮把响应的 next 作为 before，直到空页。每页条数限制在 1–100。指标接口按时间窗口查询并在较长范围内抽样。

状态码含义与处理
400Host 不被允许；使用局域网、Tailscale 地址或已配置的域名。
401凭据无效或已过期，检查令牌或重新登录。
403权限不足，或浏览器写请求缺少校验头 / 来源不匹配。
404资源不存在或历史已清理。
409版本冲突、部件未连接、频率或数量限制；按 detail 处理。
413声明的请求体超过 32 KiB。
422参数或字段不合法；detail 可为字符串或校验错误数组。
429登录失败过于频繁，五分钟后重试。
503硬件暂不可用或写入失败，检查设备及最新状态。

普通错误结构为 {"detail":"说明"}。校验错误示例：

{"detail":[{"type":"missing","loc":["body","expected_version"],"msg":"Field required","input":{}}]}
05 · WebSocket 实时状态

连接 /api/v1/live，每约 0.5 秒接收一份完整状态 JSON。推送包含设备标识，通常不包含调用者的 identity。服务器推送通道不接收控制命令；修改仍通过 HTTP API。

服务器客户端在握手时发送 Bearer 请求头；同源浏览器使用已登录的会话 Cookie。浏览器原生 WebSocket 无法设置自定义 Authorization 请求头，服务不接受 URL 查询参数中的令牌。

同源浏览器示例

const url = new URL('/api/v1/live', location.origin);
url.protocol = location.protocol === 'https:' ? 'wss:' : 'ws:';
const socket = new WebSocket(url);
socket.onmessage = event => {
  const state = JSON.parse(event.data);
  console.log(state.metrics.temperature, state.applied);
};

未认证、过期或来源不符时关闭码为 1008。断线时客户端可间隔重连，重连后使用下一份完整状态；本接口没有断点续传，历史变化请查询事件接口。

06 · 网络与硬件约定

同一实例可通过局域网和 Tailscale 地址访问。API 没有开启跨来源浏览器 CORS；独立网页可使用同源代理，服务端集成直接使用 Bearer 认证。其他树莓派有各自独立的账号与令牌。

灯珠索引为 0–13。原厂呼吸颜色和节奏由固件运行，API 返回的是模式参数与颜色示意，不是实时亮度传感器数据。机箱风扇无 RPM 反馈，CPU 风扇实际转速来自系统。

OLED 为 128×32 单色屏。pixels 解码后为 512 字节，行优先，每行 16 字节，每字节高位在左。像素 (x,y) 位于 data[y*16 + x//8] 的 7-(x%8) 位。

参数和响应模型为 OpenAPI 3.1，可下载后导入 Postman 等工具或生成客户端。各接口保留 HTTP 方法、状态码和 JSON 数据结构，客户端名称不会改变接口行为。
